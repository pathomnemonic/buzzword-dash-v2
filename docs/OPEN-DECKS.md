# Open decks

Ready-made decks the player adds with one tap. No login, no account, and every deck is published under a licence that
allows redistribution and adaptation. This page is the contract for the deck file format (section 1, FROZEN), then the
sources, pipeline, check and review results, limits and a recommendation (filled in as the pilot completes).

## 1. Deck file format (FROZEN, format 1)

Three other generators write decks in this format. Do not change field names or meanings. Additions must be optional.

A deck generator writes ONE file: `tools/opendecks/out/<deckId>.json`. The packaging step
(`node tools/opendecks/package.mjs tools/opendecks/out/<deckId>.json --source <dir>`) checks it, drops the cards that fail,
writes `public/decks/<deckId>.json` and refreshes `public/decks/index.json`.

```jsonc
{
  "format": 1,
  "id": "openstax-ap-1e",                // [a-z0-9-]{3,40}, unique, never reused for different content
  "title": "OpenStax Anatomy & Physiology: heart, vessels, lungs, kidney, hormones",
  "source": "OpenStax Anatomy & Physiology (1st edition)",   // short, shown in the list and on each card
  "licence": { "name": "CC BY 4.0", "url": "https://creativecommons.org/licenses/by/4.0/" },
  "attribution": "Adapted from OpenStax Anatomy and Physiology (1e) ... Download for free at https://openstax.org/details/books/anatomy-and-physiology. Questions generated by an AI from the text and checked automatically; not reviewed by a clinician.",
  "url": "https://openstax.org/books/anatomy-and-physiology/pages/1-introduction",  // where the source lives
  "author": "OpenStax (Rice University); questions generated by Dx Dash",
  "discipline": "physiology",            // optional: one of SOURCE_DISCIPLINES, becomes the cards' `source` (the existing source filter)
  "version": "1.0.0",                    // bump when any card changes; re-adding updates in place by card key
  "count": 123,                          // must equal cards.length (the packager recomputes it)
  "cards": [ /* card objects, below */ ]
}
```

A card is the app's runner card schema (short field names, `js/cardschema.js`) plus two provenance fields:

| field | type | rule |
|---|---|---|
| `subj` | string | one of `SUBJECTS` in `js/cardschema.js` |
| `bw` | string[] | the HINT shown on the gate. 1 to 3 clues, each at most 60 characters, together at most 130 characters (a player reads it in about 3 seconds while running). No HTML. Must not contain the answer |
| `ans` | string | the correct answer, at most 50 characters, plain text |
| `d` | [string, string] | exactly two wrong answers, at most 50 characters each; differ from `ans` and each other; plausible but clearly wrong; never "N/A", "none/all of the above" |
| `tp` | string | teaching point (the pearl), 1 to 2 sentences, at most 300 characters |
| `ww` | object | keys exactly the two strings in `d`, values one short sentence each saying why that option is wrong |
| `source_ref` | string | id of the source passage the card was written from. The checker looks for `<source dir>/<source_ref>.txt` |
| `evidence` | string | ONE sentence copied VERBATIM from that passage (whitespace, case, curly quotes normalised) which supports `ans` |
| `tags` | string[] (optional) | up to 6 tags, each at most 100 characters; they feed the importer's tag filter. The packager adds `deck:<id>` |
| `exams`, `questionType`, `baseDifficulty`, `pearls` | optional | as in the built-in cards (`EXAM_FILTERS`, `QUESTION_TYPES`, 1 to 5, string[]) |

The packager adds `key` (`<deckId>:<12 hex of a SHA-1 of source_ref + ans + evidence>`), so a card keeps its identity when its wording is
improved; do not write it yourself. The app turns each card into a custom card with `deck: <id>` and
`attr: "<source>, <licence name>"`, runner AND flashcard eligible.

Rules the checker enforces (`tools/opendecks/check.mjs`, see section 4): schema validity, evidence found in the passage,
answer supported by the evidence (lexical screen), no answer leak in the hint, distinct and non-near-duplicate options, length
limits above, no HTML, no all/none-of-the-above, no duplicate cards, and two runner-fitness rules: the answer is a short term
(at most 5 words) and a wrong answer is never just the plain-word opposite of the answer ("Both rise" / "Both fall").

Hand-off for other generators: write `tools/opendecks/out/<deckId>.json`, put each source passage in a folder as
`<source_ref>.txt`, run `node tools/opendecks/check.mjs out/<deckId>.json --source <folder>` until it is clean (or accept the drops),
then `node tools/opendecks/package.mjs out/<deckId>.json --source <folder>`. `public/decks/index.json` then lists the deck and
the app shows it with no code change.

## 2. What the app does with a deck

* Files live in `public/decks/` (same origin, so the CSP `connect-src 'self'` already allows the fetch and there is no CORS).
  They are not in the offline pack and not precached. `public/sw.js` serves `/decks/*.json` network-first and falls back to the
  last copy, so an updated deck shows at once and a deck already added needs no network at all.
* Importer, Settings > My Cards > "Bring in Anki, spreadsheet or AI cards" > **Open decks** (`js/opendecksui.js`, logic in
  `js/opendecks.js`): a collapsible "Why these decks / Add your own" blurb (text in `OPEN_DECKS_INTRO`, `js/importguide.js`, open
  the first time), then one row per deck with title, cards, size, source and licence link, **Add to my cards** (progress, Cancel,
  friendly offline errors, Try again), **Pick topics...** (the existing tag-filter panel, so the deck's tags work as a filter),
  **Remove deck**, and an **Open decks credits** section with every attribution and licence link.
* Adding uses the same `customCards.upsertMany` as an Anki import (one IndexedDB transaction, id and study history kept on
  update; cards the new version dropped are retired). Each card is stored with `deck` (id), `attr` ("Demo Book, CC BY 4.0"),
  `sref`, the deck tags and the optional discipline. Cards with two real wrong answers are runner AND flashcard eligible (the same
  rule as an AI-helper import); the player's own Anki/CSV flashcard imports stay flashcard-only. Existing subject, exam, source and
  tag filters, the "not again after a correct answer this run" rule and scoring apply unchanged because the cards are ordinary custom cards.
* The credit "Source: OpenStax Anatomy & Physiology (1st ed.), CC BY 4.0" shows under the answer in Flashcard mode, in the
  post-run review, in the quick review and under the explanation in Study.

## 3. Sources and exact licences

**Pilot deck: OpenStax *Anatomy and Physiology*, 1st edition** (the edition OpenStax now marks "retired"), chapters 17 (endocrine), 19-20
(heart, vessels), 22 (respiratory), 25-26 (urinary, fluid / electrolyte / acid-base): 22 sections, about 330,000 characters of text, saved under
`tools/opendecks/source/openstax-ap-1e/` with `manifest.json` (URLs, version, retrieval date 2026-10-12, section ids) and `LICENCE-NOTICE.txt`.

* Licence: **Creative Commons Attribution 4.0 International (CC BY 4.0)**, https://creativecommons.org/licenses/by/4.0/. Evidence: the
  copyright page of the official PDF ("Textbook content produced by OpenStax is licensed under a Creative Commons Attribution 4.0
  International License (CC BY 4.0)"), the OpenStax CMS record (`license_name` "Creative Commons Attribution License", version 4.0,
  `book_state` retired), the archive JSON of the book, and the web reader footer. Verbatim text is in `LICENCE-NOTICE.txt`.
* Attribution that the licence asks for is in each deck's `attribution` and in the credits screen: OpenStax, Rice University, the
  book URL, "Download for free at https://openstax.org/details/books/anatomy-and-physiology", a statement that the questions were
  generated by an AI from the text (the change), and the trademark notice (the OpenStax and Rice names and logos are not licensed;
  none is used). Only text is used, no figures or images.
* **Why not the current book.** OpenStax Anatomy and Physiology **2e** is **CC BY-NC-SA 4.0** (NonCommercial, ShareAlike), so it is excluded.
  The OpenStax CMS lists almost every live OpenStax title as CC BY-NC-SA 4.0 today, including Microbiology, Biology 2e, Pharmacology for
  Nurses, Medical-Surgical Nursing, Nutrition and Fundamentals of Nursing; only a few live titles (Physics, Introduction to Intellectual Property)
  and the retired earlier editions are CC BY 4.0. So the "next decks" list in the brief (Microbiology, Pharmacology for Nurses) is **not available** under a licence that permits this use.
* **Open point (needs a decision).** One templated "Attribution information" box on the 1e web page still says "CC-BY-NC-SA" although the book,
  its PDF, its metadata and its footer say CC BY. We treat the PDF copyright page as authoritative (a CC licence cannot be withdrawn from copies
  already published under it) but recommend one email to support@openstax.org to confirm before wide release.

Not used, by instruction: AnKing/AnkiWeb/AnkiHub decks, StatPearls, Wikipedia, medalpaca, MedQA, MedMCQA.

## 4. Pipeline and how to regenerate the pilot deck

```
node tools/opendecks/fetch-source.mjs         # sections.json -> source/openstax-ap-1e/<ref>.txt + manifest.json
node tools/opendecks/build.mjs                # writes batches/<ref>.prompt.txt (the app's own prompt + passage) and,
                                              # from replies/*.json (+ replies-r2, replies-r3), out/openstax-ap-1e.candidates.json
node tools/opendecks/check.mjs tools/opendecks/out/openstax-ap-1e.candidates.json --source tools/opendecks/source/openstax-ap-1e
node tools/opendecks/package.mjs tools/opendecks/out/openstax-ap-1e.candidates.json --source tools/opendecks/source/openstax-ap-1e
node tools/opendecks/sample.mjs tools/opendecks/out/openstax-ap-1e.candidates.json --source tools/opendecks/source/openstax-ap-1e --n 60 --seed 20261012
```

1. **Source**: the OpenStax archive JSON for each section is turned into plain text.
2. **Generate**: `buildAiPrompt()` (the app's own prompt, `js/importguide.js`) plus a short extra block (passage id, one-sentence `evidence`, hint and answer length) and the passage
   is the instruction; the model (Claude, acting as the player's AI chat) writes a JSON reply per passage into `replies/<ref>.json`. The first two passes were written
   against the earlier version of the prompt; the app prompt was tightened during the pilot (no opposites as wrong answers, answers are terms, clue words) and the parser
   gained quality screens, which this pipeline uses unchanged (`parseAiReply` is the real parser, not a copy).
3. **Parse**: the real parser keeps `source_ref` and `evidence` (a two-line addition to `normalizeAiCard`).
4. **Check** (`check.mjs`), 5. **Repair**: cards that fail are regenerated once (`replies-r2`), 6. **Independent review** and fixes (`replies-r3`, `review-drops.json`), 7. **Package**.

## 5. Automatic check results (pilot)

| stage | cards |
|---|---|
| written by the model, 22 passages | 390 |
| kept by the app's real reply parser | 375 (15 skipped: 10 "a clue gave the answer away", 4 "answer was a whole sentence", 1 duplicate) |
| pass every check first time | 290 of 375 (77.3%) |
| failed | 85: 47 length (hint or clue too long for a 3-second read, mostly by a few characters), 36 runner-fitness (sentence answers, opposite wrong answers), 3 answer not supported by the evidence sentence, 1 hint leaks the answer, 1 evidence not a single sentence, 1 near-duplicate options |
| regenerated after failing | 51 rewritten, 47 pass the final rules |
| independent review: dropped / rewritten | 14 dropped, 10 rewritten (all pass) |
| **shipped** | **333 cards** (Cardiology 127, Nephrology 73, Endocrinology 69, Pulmonology 64) in `public/decks/openstax-ap-1e.json`, 249 KB |

Candidate-to-keep yield: 333 of 390 written (85%); 276 of 390 (71%) as first drafted. Evidence-in-passage and the lexical answer screen
rejected only 4 cards because the model was asked to quote; that is the point of the field, but see limits. Notes: the parser's own "clue gave the answer away" screen
is a false positive for some short answers ("T wave" with the clue "ECG wave"); 15 of 390 is an acceptable loss.

## 6. Independent review (60 random passing cards)

Method: seeded random sample (seed 20261012) of 60 cards that passed all checks. For each, the passage was read again (the paragraph holding the
evidence sentence and its neighbours) and the card graded without using the generation step's claims, also against standard physiology teaching.
Same model graded its own output, which is a real limitation (correlated blind spots; see section 8).

| grade | cards | share |
|---|---|---|
| correct (supported by the passage and standard teaching) | 56 | 93% |
| partly right (source-faithful but simplified, or an arguable wrong answer) | 4 | 7% |
| wrong | 0 | 0% (upper bound about 5% at this sample size) |
| unsupported by the source | 0 | 0% (the evidence check makes this near impossible by construction) |

Runner fitness (clue answerable at a glance, exactly one defensible answer among the three gates, wrong answers plausible but wrong):

| grade | cards | share |
|---|---|---|
| good | 42 | 70% |
| acceptable (weak distractor, number trivia, slightly vague stem) | 13 | 22% |
| poor | 5 | 8% |

**Five good cards** (hint -> answer; wrong answers)
1. "Largest total cross-sectional area in the body" -> Capillary beds; Arterioles / Veins
2. "Deepest zone of the adrenal cortex | Produces small amounts of androgens" -> Zona reticularis; Zona glomerulosa / Zona fasciculata
3. "Plant polysaccharide | Neither reabsorbed nor secreted | Given IV to estimate GFR" -> Inulin; Glucose / Urea
4. "Hyponatremia | Water enters cells by osmosis | Effect on cells" -> Cells swell, risking brain damage; Cells shrink and dehydrate / Cells are unaffected
5. "Prednisone and hydrocortisone cream | Cortisol effect on immunity" -> Immune system suppressed, less inflammation; boosted, more inflammation / Selective destruction of B cells

**Five bad or weak cards**
1. Angiotensin II "in blood loss or dehydration" -> "GFR and renal blood flow fall" (source sentence, but it contradicts standard teaching that Ang II keeps GFR up by constricting the efferent arteriole and contradicts the book's own chapter 26; a wrong answer, "GFR rises while renal blood flow falls", is arguably the textbook answer). Dropped.
2. "Exhaling CO2 raises blood pH | Time this takes" -> Minutes; Seconds / Hours to days. Correct but the stem never says what is asked and the three time-scale cards confuse each other. Dropped, replaced by two cards with a clear stem ("Fastest way the blood adjusts pH" -> Chemical buffers).
3. "Tachycardia correlated with fever, anemia and hypoxia | State of excess thyroid hormone" -> Hyperthyroidism. The second clue restates the answer. Dropped.
4. "High blood phosphate | Decreased renal function | ..." -> Hyperphosphatemia. A prefix lookup, not a question; same for Hypo-phosphatemia, Hypo/Hypervolemia, Hypo/Hypercapnia, Hyponatremia, Hyperkalemia (9 more cards found by search). Rewritten without the restating clue.
5. "Slows heart rate, strengthens contraction | Blocks calcium uptake by the SR" -> Digitalis. Source-faithful, but the standard mechanism is Na+/K+-ATPase inhibition, so the clue teaches a simplification. Kept, flagged "partly right".

**Failure patterns of the AI pipeline**
* Restating the answer in the hint (hyper-/hypo- words, "excess X" -> "hyperX"): about one card in seven of the disease-name cards.
* Opposites as wrong answers ("Both rise" / "Both fall", "More ..., less ..." reversed): common when the fact is a direction; now a check.
* Sentence answers and over-long hints: the model writes explanations, not terms; the checks and the stricter app prompt fix most of it.
* Number trivia (7-10 percent, 70-80 percent, 64 mm Hg): supported, low value, wrong answers are arbitrary numbers.
* Copying the source's mistakes faithfully. Examples found while reading: "stimulates the adrenal cortex to secrete epinephrine" (it is the medulla), calcium for cardiac contraction "mostly from outside the cell" and "about 20 percent from outside" in the same section, "treatment for diabetic coma is ingestion or injection of sugar" for ketoacidosis, angiotensin II raising GFR in one chapter and lowering it in another, hyperkalemia as a "weak, flaccid" heart in one and a heart that "will not relax" in another, phosphate "85 percent" versus "over 90 percent" in bone. The evidence check cannot catch these because the model quoted the book. The cards built on the clearly wrong ones were avoided or dropped.
* Wrong answers that are also correct in real physiology (lymphatic capillaries as "gaps large enough for proteins"; the Ang II case above).
* Meta wording in the why-wrong text ("The source does not describe ..."): harmless but unfriendly; worth a check later.

## 7. Limits

* Content is only as good as a 2013 first edition (retired); the newer 2e is not usable. Several USMLE topics are shallow (no pathology, drugs, vignettes): the questions are physiology recall, not exam-style stems.
* No clinician has reviewed any card. The deck says so on the card list, in the credits and in the blurb.
* The review sample is small and graded by the same model family; 0 wrong in 60 is encouraging, not proof.
* The lexical "answer supported" screen is cheap: it checks words, not meaning.
* Not tested on devices other than desktop Chromium at 390x780 (see `docs/opendecks-shots/`).

## 8. Recommendation

The AI output is sensible enough to ship this one deck as a **study aid**, with the "not checked for exam accuracy" wording kept, and to scale **to more openly licensed
text**, because the failure modes are mechanical and are caught by `check.mjs` plus one human skim; but not to call anything "exam accurate" yet.
* Scale only where the licence is clear: MedlinePlus / NIH / CDC pages (US government, public domain, check each page for third-party material), open-access CC BY chapters from the NCBI Bookshelf / PMC OA subset after reading each book's licence, and retired OpenStax editions that are CC BY (verify each). Live OpenStax books (Microbiology, Pharmacology for Nurses) are CC BY-NC-SA and are out.
* Before telling players a deck is exam-accurate: a clinician or senior student should read a sample of at least 100 cards per deck, plus every card on drug mechanisms and dosing; fix source errors listed in section 6; re-run the review after any prompt change; keep the "AI-written, not clinically reviewed" line until then.
* Cheap improvements: a "restates the answer" check (hint word inside the answer), a cap on number-only cards per section, and replacing the meta wording in why-wrong text.
